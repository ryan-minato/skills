# Meta Skills

Disposable, project-scoped builders for creating a durable agent harness. Install
the catalog for a harness build, deposit every lasting rule into the target
project, verify it, then remove the builders with `meta-disposal`. Their shared
description prefix identifies them as temporary, allowing this catalog to give
project initialization complete guidance without carrying that context into
normal development.

| Skill | Purpose |
|---|---|
| [meta-harness-building](meta-harness-building/) | The single entry to every harness build, improvement, or repair: learn the repository, settle the requirement with the user, plan with approval, build each layer through the skills at hand, read the result back in a clean context, review it for builder-only vocabulary, keep the builders out of every commit, and close by asking whether to remove them before review. |
| [meta-harness-architecture](meta-harness-architecture/) | The architecture practice manual the entry loads layer by layer: design axes, entrypoints, knowledge, project skills, synchronization, entropy management, multi-agent topology, and advanced autonomy, with starting-shape assets. |
| [meta-workflow-design](meta-workflow-design/) | Co-design a project's platform-neutral management model with its human developers — the work-tracking semantics the project actually earns, a workflow profile matching how it really ships, overlays and change-propagation risks — and deposit the workflow contract the platform builders map instead of re-deciding. |
| [meta-spec-workflow](meta-spec-workflow/) | Align the harness and work tracking with spec-driven development: settle the specification level and tool with the user (Spec-Kit, OpenSpec, Kiro, or committed documents), install or adopt the tool's layout, give every fact one source of truth between tool-owned files and the entrypoint or knowledge base, and deposit the specification contract that the platform builders express as templates and workflow steps. |
| [meta-agent-authority](meta-agent-authority/) | Design the human–agent governance policy — authority levels H0–H3, the review-admission and integration gates, escalation conditions, and the rule that agents never widen their own authority — and deposit it as a durable policy the project's agents obey at runtime. |
| [meta-github-workflow](meta-github-workflow/) | Build or systematically repair a complete GitHub repository lifecycle harness for GitHub.com or GitHub Enterprise, designed around the pull-request loop: intake forms and Discussions routing, labels extending the defaults, tracking issues and milestones, early draft PRs via issue-linked branches, Actions quality gates and community automation, rulesets, CODEOWNERS, releases with label-driven notes, registries, optional Projects and ML experiment records, and durable project-agent workflows. |
| [meta-gitlab-workflow](meta-gitlab-workflow/) | Build or systematically repair a complete GitLab project lifecycle harness for gitlab.com or self-managed instances: planning, work items and early draft MRs, community files, CI/CD, governance, security, Wiki, releases, deployments, registries, optional MLOps, and durable project-agent workflows. |
| [meta-git-branching](meta-git-branching/) | Select the git branching model a project's releases and deployments earn — git flow, GitHub Flow, or a GitLab Flow variant — settle branch, tag, protection, and merge-method conventions with the team, enforce what the host can enforce, and deposit the contract as event-triggered project knowledge. |
| [meta-gpu-container](meta-gpu-container/) | Establish GPU container environments for a project of any domain: judge whether a container is warranted, select and live-verify a current CUDA or ROCm base image, wire GPU access into docker run, Compose, and dev containers, and deposit the resulting rules into the target harness. |
| [meta-disposal](meta-disposal/) | Dry-run and remove every copied disposable builder of the `meta` and `scaffold` catalogs once the user has decided to delete them, without touching durable skills. |
| [meta-python-defaults](meta-python-defaults/) | Choose missing Python documentation, testing, and toolchain conventions without replacing working choices. |
