# Periodic Entropy Reclamation

Read when the project is long-lived. Realtime sync catches drift at edit
time; the periodic routine catches what nobody edited — documents that
quietly went stale while attention was elsewhere. Encouraged for every
long-lived project, mandatory for self-evolving harnesses.

## The Checklist

Each run walks every harness component and hunts:

- stale paths and dead commands (run them; do not trust them);
- rules the code now contradicts;
- the same rule stated in two places;
- content unreachable from the entrypoint;
- triggers that can no longer fire (their subject moved or vanished);
- thickness beyond what the project's traits still justify;
- section-locating pointers whose byte-exact headings no longer match.

Every finding gets a disposition — update, reconnect, merge, thin, or
delete — applied or reported in the same run. Deleting stale content is a
success, not a loss: reclaimed context is the point.

## Cadence

Pick by change velocity, not by calendar preference: fast-moving projects
monthly, slower ones quarterly. Anchor the cadence to something the team
already does on a rhythm (a release, a retro) so the routine has a
trigger, not just an intention.

## Installing

- Skill family: a durable routine skill triggered by the anchor event or
  an explicit request ("reclaim the harness", "harness audit").
- Entrypoint family: a dated section in the entrypoint or a knowledge doc
  — the checklist, the cadence, the anchor, and the date of the last run
  (absolute dates only).
