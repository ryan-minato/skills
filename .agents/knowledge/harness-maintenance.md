# Harness Maintenance

Read this when a file that another file mirrors changes, when a tool pin
is bumped, on the first pull request of each quarter, and whenever a
catalog is added or removed. It holds the two things that keep this
harness true to the repository: the register of copied facts and their
owners, and the periodic entropy review.

Decision on record (2026-09-03, maintainer): GitHub is this repository's
only remote and task platform. The knowledge files are written in GitHub
terms, as every `meta` contract builder deposits them; only the builders'
disposal step does not apply here (see `## Use inside this repository` in
`skills/meta/CONTEXT.md` and `skills/scaffold/CONTEXT.md`).

`just validate`, pre-commit, and `checks / quality`); its docstring lists

## Periodic entropy review

Cadence: quarterly, on the first pull request of the quarter, and after
any catalog change. Last run: 2026-09-03 (the harness rebuild).

1. Run `just check`; every documented command in `AGENTS.md`,
   `ARCHITECTURE.md`, and the project skills must still run.
2. Read `AGENTS.md` for length (about 100 lines), stale paths, and rules
   stated twice; every knowledge file must still have a pointer whose
   trigger can fire.
3. Compare each knowledge file's "Update this file when" list with what
   actually changed since the last run; update or delete stale content.
4. Compare `.agents/knowledge/github-settings.md` with a fresh readback of
   every row.
5. Check the "not used" triggers in `.agents/knowledge/github-workflow.md`
   and the omitted-object list; enable only what fired.
6. Look for constraints thicker than the work justifies and for project
   skills whose trigger never fired since the last run.
7. Record findings as keep / update / remove, apply the unambiguous ones,
   and update the "Last run" date above in the same pull request.
