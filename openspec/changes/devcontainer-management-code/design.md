## Decisions

Settled by the maintainer before the draft:

- **A required test file that is missing fails; an optional one is skipped visibly** (Template test script; CLI skips).
  - A template without `test/<id>/test.sh` fails naming it, because `template-scaffold/AGENTS.md` requires one.
  - A feature without `scenarios.json`, or a collection without `test/_global/scenarios.json`, is skipped with a `::notice::` naming the file and a comment where the skip is decided, because the scaffolds treat both as optional.
  - Rejected: leaving the CLI's warning in a green log (a vacuous pass).
  - Rejected: failing on the optional files, which would force empty scenario sets on every collection.
- **`compatibility.txt`: a missing file keeps the documented default; a file that declares no image fails** (Feature collection). The default is design, stated in the action's description. An empty claim hides a feature that is never tested.
  - Rejected: failing on both, which breaks the documented contract.
  - Rejected: keeping both, which hides the empty claim.
- **The reference's idempotency check is in scope** (Feature tests the agent writes). `feature-testing.md:82` is the same rule class, and the skill tells agents to write it. It is replaced by the duplicate mode.
  - Rejected: a separate issue, which leaves the skill teaching the pattern this change removes from its assets.
- **The scripts stay in Bash** (all Behavior requirements). The Dev Container ecosystem scripts in Bash (feature-starter, template-starter, devcontainers/features), `management-code.md` delivers a deposited asset in the language it ships in, and the issue is about failure hiding.
  - Rejected: a port of `smoke.sh` and the recipes to TypeScript or Python, which would be its own change.
- **Verification uses stubs** (Verification plan). The live Docker and GitHub Actions cases are recorded as skipped, and the CLI facts are cited from upstream source with a date (Context).
  - Rejected for now: a throwaway GitHub repository or a Docker host. It stays open if the maintainer later authorizes one.
- **No shellcheck lint companion.** Bash assets under `skills/` are unlinted by `just lint`, but a lint scope change touches the `justfile`, `.pre-commit-config.yaml`, `ARCHITECTURE.md`, and the tool pins. It is proposed as a separate repository issue, and this change runs shellcheck ad hoc in verification.
- **Commit type `fix`.** The scaffolds read failures as success and reject valid defaults. The issue's `enhancement` label does not decide the type.

Design bounds (all requirements):

- **Only a step that hides a failure is rewritten.** Conforming steps stay byte for byte: path-filter generation, the CLI installs, the mode `case` with its exit 2, the shellcheck `-S error` threshold, the main-only release guard, the empty feature list on a collection with no features, and the `set -e` plus `check`/`reportResults` test style.
  - Rejected: a blanket restyle, which makes review noisy.
- **Each interface is checked once, where its data enters, and read directly afterwards:**
  - the `features` input's JSON shape, naming the input and the value;
  - the template manifest, parsed once;
  - an option's `default`, tested for presence rather than truthiness.
  - Rejected: `|| exit 1` on every line, or a `set -E` ERR trap. Neither names the interface.
- **Command output is captured into a variable before any loop, condition, or `echo` uses it.** A plain assignment carries the command's status under errexit.
  - Rejected: `shopt -s inherit_errexit` alone. It does not cover process substitution, and readers miss it.
- **The example feature checks capture the tool's output under its own status, then match it.**
  - Rejected: `set -o pipefail` inside `bash -c`. When `grep -q` exits at its first match, the producer can die of SIGPIPE, and a passing check fails.
- **The release documentation step branches on the exit status of `git diff --cached --quiet`.** 0 means no change, 1 means commit, push, and open the pull request, and anything else fails. The commit then runs outside any condition.
  - Rejected: `git commit || true`, which is wider than intended.
  - Rejected: `git status --porcelain` inside an `if`, which again tests a command inside a condition.
- **Smoke cleanup stays best effort and is marked.** It warns on stderr naming what it could not remove, and never changes the exit status of the test.
  - Rejected: failing the run on a cleanup error, which masks a real test result. Leftover containers on an ephemeral runner are harmless.
  - Rejected: keeping `>/dev/null 2>&1 || true`.
- **`smoke.sh` is invoked through `bash` by the action and the recipe**, so a lost exec bit does not matter.
  - Rejected: relying on the copier's `chmod`, or on mode 100755 alone, which installers may not preserve.
- **The `!= ''` guards are dropped.** `dorny/paths-filter@v3` never writes an empty `changes` (Context), so the guards cannot fire today. They are removed because they are a default that would stand in for a failure: if an empty value ever arrived, from a hand edit of the action or a later filter version, they would skip the test job instead of failing the run.
  - Rejected: keeping them as harmless dead code, which leaves a silent skip ready for the day the input changes.
- **`validate` collects every malformed manifest and fails once, the deferral marked**, as `management-code.md` recommends for checks over committed files.
  - Rejected: stopping at the first failure. It is correct, but it hides the other broken files until the next run.

## Risks / Trade-offs

- **[CLI behavior this environment cannot run: no Docker, no devcontainer CLI]** → The shell logic is proven with stubs. The CLI facts are cited from the pinned version's source with the date (Context). The live cases are listed as skipped.
- **[A later CLI release changes the skip messages or starts failing on a missing file]** → The presence checks run before the CLI and do not parse its output, so they hold either way. The reference cites 0.87.0.
- **[Over-application turns a designed deferral into a failure]** Examples are `fail-fast: false`, the main-only release guard, the optional scenario sets, and the documented default image. → They are named as conforming or as marked skips above, and the outcome rubrics treat a lost deferral as a failure.
- **[The two scaffolds drift on the shared constructs]** → Each shared construct's harness runs on both scaffolds.
- **[Locally, `just test-scenarios <id>` and `just test-global` exit 0 when their optional file is missing]** The only signal is the CLI's skip warning in the terminal. → The files are optional by design, the warning names what was skipped, and CI announces the same skip with a notice. `duplicate.sh`, the required file, fails locally as in CI.
- **[Requiring `duplicate.sh` adds a file to every new feature]** → The example ships one, `AGENTS.md` and the reference name it, and the failure message says which file to add.
- **[Stubbed `devcontainer exec` hides a container-side difference]** → The stub runs the command the smoke script passes, through the same shell the smoke script names, so the host-side logic is what is under test. Container-side behavior belongs to the skipped live run.
