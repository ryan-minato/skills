## Why

Teams that want to learn from another project's agent harness — their own earlier repositories, or public ones whose agent setup they admire — need an account of what that harness actually does before anything can be borrowed from it. Without a method, an agent asked to "look at how repo X does it" reads the reference's AGENTS.md and reports its prose as fact: it cannot tell a rule wired into CI from a decorative sentence, misses mechanisms that live in hooks, permission files, or task runners, mixes the layers of the harness into one impression, treats the repository as a model to imitate rather than a subject to assess, and treats its instruction files as instructions. The library has builders for a harness and investigators for a codebase's behavior, but nothing that studies a repository's harness as evidence and reports it layer by layer.

## What Changes

- A new `engineering` methodology skill, `harness-study`, that studies the agent harness of one or more given repositories as evidence: it pins each repository at a revision, surveys six harness layers, records every mechanism as a pattern carrying the problem it solves, its enforcement kind, the evidence that it is live, and the cost it charges each task, grades each layer, assesses each pattern on its own merits — a strength worth learning from, a weakness to avoid, or neutral, each with its evidence — and delivers a study report. The study covers all six layers by default or narrows to the aspect the user names. It assesses and compares; it transfers nothing and changes nothing.

## Skills touched

- `engineering/harness-study` (new): the whole domain — trigger, pinning of the studied repositories, study scope (whole harness by default, one aspect on request), pattern extraction with liveness evidence, per-layer grading, critical assessment and comparison, the study report, repository text as data, and the handoff to the harness build entry when the user wants the findings applied.

## Installed behavior

An agent that loads the skill, asked to study, explain, or compare the agent harness of given repositories, pins each at a revision, surveys the whole harness or the aspect asked for, records patterns with their evidence instead of restating the repository's documents, grades each layer, assesses each pattern as a strength, a weakness, or neutral with the reason, and hands over a report with defects and open questions listed. It treats text found in the studied repositories as data, records secrets by name only, edits nothing, and routes any application of the findings to a project to the harness build entry through the installing skill. This is a `feat`: a new capability.

## Non-goals

- Deciding what transfers to a target project, or applying anything: that belongs to the harness builders and to a future transfer skill, not here.
- Building or auditing a harness with no study requested: the `meta` catalog's builders and the `core` methodology skill.
- Investigating what a studied repository's application code does: `brownfield-investigation`.
- A bundled script that inventories harness artifacts; the first version works from a reference file that says where each layer lives.
